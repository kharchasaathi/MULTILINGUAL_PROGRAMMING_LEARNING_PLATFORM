# CodeSaathi Curriculum Master Syllabus — Version 1.0

**Status:** Curriculum baseline — detailed lesson authoring and review pending  
**Release focus:** HTML, CSS, JavaScript  
**Teaching languages:** Telugu and English first; architecture must support Malayalam, Kannada, Tamil, and Hindi  
**Reference policy:** Use W3Schools only as a topic-coverage cross-check. All teaching text, examples, diagrams, exercises, projects, and UI assets must be original to CodeSaathi. No external brands, product names, company catalogues, or proprietary codes in learner-facing material.

## 1. Curriculum promise

A learner who completes this pathway should be able to plan, build, style, make interactive, debug, and publish responsive websites using semantic HTML, modern CSS, and browser JavaScript. The pathway moves from absolute beginner to practical project builder.

This syllabus is a coverage plan, not a claim that lessons are already written or tested. Each topic must pass the lesson definition-of-done in `PRODUCT_DESIGN_AND_LEARNING_EXPERIENCE_SPEC.md`.

## 2. Mandatory lesson format

Every lesson has three stages:

1. **Understand** — plain-language concept, problem solved, relevant history/evolution and name origin where useful and verified.
2. **See it explained** — original example explained like a human teacher, step by step, with a relatable analogy and its limits.
3. **Write, run, observe, practise** — editable code, real isolated live output for executable code, guided task, independent challenge, quiz, and feedback.

Every executable example across HTML, CSS, and JavaScript must have a live output appropriate to that code. CSS lessons additionally include a CodeSaathi-owned colour/property lab with visible standard CSS codes. No external brand references.

## 8. Assessment model

Each module should include:
- Short recall quiz
- Concept-understanding question requiring explanation in the learner's own words
- Code-reading task
- Modify-and-observe task in the live playground
- Independent build challenge
- Review rubric with correctness, clarity, accessibility, responsiveness, and code quality

Do not award completion based only on opening a page or pressing Run. Record completion against explicit learning outcomes.

## 9. Topic tracking and release gates

Use these statuses per topic: `PLANNED`, `OUTLINED`, `CONTENT_DRAFTED`, `TECHNICALLY_REVIEWED`, `TELUGU_REVIEWED`, `ENGLISH_REVIEWED`, `PLAYGROUND_TESTED`, `ACCESSIBILITY_CHECKED`, `RELEASED`.

A course may be labelled complete only when every required topic in its agreed release scope is released, every executable example has verified live output, all lesson stages are present, and the course-level assessment passes.

Suggested first-release sequence:
1. Foundation F0–F1
2. HTML H1–H10 and projects
3. CSS C1–C14 and projects
4. JavaScript J1–J13 and projects
5. Integrated P1–P3 and capstone
6. Telugu/English content quality and language persistence validation

## 10. Explicit exclusions from the first course scope

These may become later courses, but must not be silently mixed into the beginner HTML/CSS/JavaScript promise:
- TypeScript
- Frontend frameworks and libraries
- Backend frameworks and server architecture
- Databases and advanced authentication
- Native Android/iOS development
- Build tooling and package ecosystems beyond what is needed to explain the browser basics

The curriculum architecture must leave room for future courses.

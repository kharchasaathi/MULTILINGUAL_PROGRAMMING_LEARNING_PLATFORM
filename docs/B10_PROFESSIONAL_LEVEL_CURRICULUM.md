# B10 — Professional Level Curriculum

**Status:** Defined  
**Exclusive curriculum source:** W3Schools  
**Depends on:** B7 Beginner, B8 Intermediate and B9 Advanced  
**Artifacts:** `docs/B10_PROFESSIONAL_LEVEL_CURRICULUM.md`, `docs/B10_PROFESSIONAL_LEVEL_MAP.csv`

## 1. Purpose

B10 defines the professional application of the W3Schools curriculum. It is not a promise of job placement, certification or mastery of every listed technology. It organizes selected W3Schools tracks into portfolio-oriented, maintainable and demonstrable work.

Professional-level learners should be able to plan a deliverable, choose a relevant W3Schools technology path, build a coherent solution, use the relevant references and exercises, explain trade-offs, and present the result.

## 2. Entry requirements

Learners should have:
- Completed the relevant B7–B9 foundations and selected a primary specialization.
- Built at least one independent intermediate project and one advanced capstone.
- Used the relevant language, framework and data topics from W3Schools.
- Demonstrated the ability to debug and explain their own code.
- Completed the DSA pathway when it is a prerequisite for their selected specialization.

## 3. Professional outcomes

By the end of B10, learners should be able to:
1. Select a coherent W3Schools technology stack for a defined project.
2. Translate a project brief into pages, components, data structures and database tasks.
3. Build a complete project using the selected frontend, programming and data tracks.
4. Organize code into reusable files, modules, functions, classes and components where supported by the chosen track.
5. Use the relevant SQL/database, JSON, API and asynchronous topics where they are part of the selected W3Schools path.
6. Use Git topics from W3Schools to maintain a project history.
7. Demonstrate, document and present a portfolio-ready result with setup and usage instructions.

## 4. Specialization pathways

A learner chooses one primary professional pathway and may add related electives. Not every learner must study all tracks.

### 4.1 Frontend web developer
- HTML: semantic page structure, forms, media and browser features in the tutorial.
- CSS: responsive design, Flexbox, Grid, effects, layout and styling.
- JavaScript: DOM, events, classes, modules, async, JSON, Fetch, AJAX and Web APIs.
- Optional W3Schools-listed extensions: Bootstrap, React, Vue, Angular, jQuery, TypeScript.

### 4.2 Backend and application developer
- Choose one W3Schools programming language track such as Python, Java, PHP, C#, C++ or another listed language.
- Use the language's functions, modules, classes and error-handling topics where available.
- Add a W3Schools-listed backend track such as Node.js, Django or ASP when relevant.
- Use JSON, AJAX and related data exchange topics where present in the chosen path.

### 4.3 Database and data application developer
- SQL: multi-table queries, grouping, constraints, indexes, views, stored procedures, parameters and prepared statements.
- Choose a W3Schools-listed database path such as MySQL, PostgreSQL or MongoDB.
- Add Python, PHP, Java or another W3Schools programming track as needed.
- Deliver a working data application or reporting solution.

### 4.4 Data analytics and data science
- W3Schools Data Science, Statistics, Excel and Google Sheets topics.
- Python, NumPy, Pandas, SciPy and Matplotlib tracks where selected.
- AI and Machine Learning topics where included in the chosen learning path.
- Deliver an analysis/reporting project with explainable steps and outputs.

### 4.5 Cloud, security and developer workflow electives
- W3Schools Git and Bash tutorials.
- W3Schools AWS Cloud and Cyber Security tutorial tracks.
- Use these as focused electives; do not treat a catalogue listing as a complete professional certification or production-readiness guarantee.

## 5. Professional project lifecycle

Each professional project follows these learning stages:
1. **Brief:** define the user problem, expected behavior and project boundaries.
2. **Track selection:** identify only the relevant W3Schools technologies and prerequisite topics.
3. **Design:** sketch page structure, navigation, data model and module boundaries using concepts in the selected tracks.
4. **Build:** implement the application in small, understandable increments.
5. **Practice:** complete relevant W3Schools examples/exercises and independently adapt the concepts.
6. **Test:** prepare normal, boundary and invalid-input examples; verify expected behavior manually or with the testing approach available in the project.
7. **Improve:** revise code organization, responsiveness, readability and query/algorithm choices.
8. **Present:** provide project overview, setup instructions, usage guide, screenshots or demonstration, and a short explanation of decisions.

This lifecycle is an instructional workflow, not an assertion that W3Schools provides a full professional software delivery methodology.

## 6. Portfolio deliverables

Each learner should complete at least one substantial project in their chosen specialization. Appropriate deliverable types include:
- Responsive multi-page website or interactive web application.
- Backend application using one selected W3Schools language/framework path.
- Database-backed application with relational queries and a selected W3Schools database track.
- Data analysis/reporting project using the selected W3Schools data topics.
- Git-managed code portfolio containing the project and its history.

Required evidence:
- Project brief and scope.
- Source code organized for the selected track.
- Setup and usage instructions.
- Sample input and expected output.
- Test scenarios and recorded results.
- Short architecture/data-flow explanation.
- Demonstration or screenshots.
- Reflection describing limitations and next improvements.

## 7. Professional practice standards

The platform's learning rubric should assess:
- Correctness against the stated requirements.
- Clear and maintainable organization using concepts from the selected W3Schools track.
- Appropriate use of HTML/CSS/JavaScript, language, framework and database topics.
- Responsive behavior where the project is web-based.
- Data handling and query correctness where applicable.
- Meaningful test cases and honest reporting of results.
- Clear documentation and explanation.
- Independent work and proper attribution of external material.

Do not claim that completing B10 alone proves industry certification, security compliance, production scalability or employment readiness.

## 8. Assessment rubric

Score each applicable dimension from 0 to 4:
- 0 — Not demonstrated
- 1 — Requires substantial guidance
- 2 — Partially independent; important gaps remain
- 3 — Independently meets the project requirement
- 4 — Strong, clear and well-explained implementation

Dimensions: requirements, implementation correctness, code organization, responsive/UI behavior, data handling, testing, documentation and presentation. Mark a dimension not applicable only when the selected project genuinely does not use it. Completion requires at least level 3 on all applicable dimensions and no unresolved critical failure in the submitted project.

## 9. Boundaries

B10 is a professional learning and portfolio definition, not a job guarantee, formal credential, external certification, or full production engineering standard. Deep deployment, operations, architecture, security and quality engineering are handled by the platform's separate D, E and F workstreams. Use only topics and technologies represented on W3Schools; do not silently add vendor or third-party syllabus items.

## 10. Completion criteria and handoff

B10 is complete at professional-level scope and pathway-map definition when:
- The primary specialization pathways and prerequisites are documented.
- Professional project lifecycle and portfolio deliverables are defined.
- Assessment rubric and completion criteria are recorded.
- The map contains W3Schools source links and practice entry points.
- Optional tracks are clearly distinguished from required core learning.
